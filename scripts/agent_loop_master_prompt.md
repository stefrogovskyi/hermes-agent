# UNIVERSAL PROMPT — «Текстовый бот → полноценный агент-луп» (реверс с Лиз Харпер)

> Используй этот промпт целиком. Подставь значения в [СКОБКАХ]. Он выведен
> реверс-инжинирингом рабочей сущности Liz Harper (Enlight Group) на ядре
> hermes-agent и включает все выстраданные уроки (409, токены, локи, дубли).

---

## ПРОМПТ (копируй отсюда)

Ты — инженер мультиагентных систем. Преврати текстового Telegram-бота в
полноценного автономного агента по следующей спецификации. Язык кода — Python,
только stdlib для транспорта (urllib, threading, json, os), без aiogram/PTB.

### 1. РОЛЬ И ЛИЧНОСТЬ
- Агент: [ИМЯ], [ДОЛЖНОСТЬ] компании [КОМПАНИЯ], зона ответственности: [SCOPE].
- Личность и стиль — в отдельном файле `system_prompt.md` (единственный
  источник истины личности). Знания домена — в `Agents.md`. Код читает оба
  при старте и склеивает в системный промпт.
- Агент — НЕ чат-обёртка: у него есть инструменты (file, memory, [ДРУГИЕ]),
  собственная память на диске и место в иерархии мультиагентной системы:
  оркестратор — [ОРКЕСТРАТОР], коллеги — [СПИСОК АГЕНТОВ]. Агент не дёргает
  чужих агентов напрямую — только через оркестратора или общие файлы
  (outbox/tracker), эскалации — владельцу [ВЛАДЕЛЕЦ, chat_id].

### 2. АРХИТЕКТУРА (агент-луп, не webhook)
- Один процесс, один вечный цикл: long-poll Telegram getUpdates(timeout=30)
  → фильтр → мозг (LLM с tool-calling) → ответ → снова poll.
- Мозг: класс AIAgent из ядра [ЯДРО, напр. hermes-agent run_agent.py]:
  model=[МОДЕЛЬ], enabled_toolsets=[file, memory], quiet_mode=True,
  ephemeral_system_prompt=личность, session_id="[имя]_{chat_id}",
  fallback_model=цепочка бесплатных моделей (hot-reload из free_models.json).
- Отдельный экземпляр AIAgent на каждый chat_id (dict + threading.Lock) —
  у каждого собеседника свой контекст и своя память диалога.
- Память: персональная история на юзера, в группах — двойной контекст
  (g:{group_id} общий + gu:{group_id}:{user_id} персональный).

### 3. ТРАНСПОРТ — ЖЕЛЕЗНЫЕ ПРАВИЛА (уроки продакшена)
1. ТОКЕН: читать ТОЛЬКО из СВОЕГО .env.local (папка агента). НИКОГДА из
   os.environ — среда запуска несёт чужой токен (оркестратора) → агент
   поллит чужого бота → вечный 409 Conflict. При старте логировать
   bot id из токена (token.split(":")[0]) для самопроверки.
2. SINGLE INSTANCE: pid-lock файл ([имя].lock) через os.O_CREAT|os.O_EXCL;
   проверка живости старого pid — ТОЛЬКО ctypes.OpenProcess (tasklist
   зависает под pythonw). Второй экземпляр молча выходит.
3. getUpdates: GET с query-string, retry=False (retry внутри = второй
   параллельный long-poll = 409). Один вызов на итерацию цикла.
4. ОБРАБОТКА ОШИБОК POLL: любая ошибка (включая 409) → log + sleep(10) +
   retry. БЕЗ deleteWebhook, БЕЗ getUpdates?offset=-1, БЕЗ長 пауз — призрак
   от прошлого инстанса истекает сам за ~35 сек.
5. ПЕРЕЗАПУСК: убил процесс → жди 35-40 сек ДО старта нового (иначе
   Telegram держит старый long-poll и новый ловит 409).
6. ЗАПУСК: pythonw (uv/base), НЕ venv python (venv-launcher спавнит
   дочерний процесс → два поллера → 409). Никаких консольных окон:
   CREATE_NO_WINDOW, лог в файл.
7. sendMessage: резать по 4000 символов; sendChatAction typing перед
   долгим ответом.

### 4. ФИЛЬТР СРАБАТЫВАНИЯ (группы)
- Личка: отвечать всегда.
- Группа: отвечать ТОЛЬКО на (а) @упоминание бота, (б) имя агента в тексте
  [ИМЯ+ВАРИАНТЫ], (в) reply на его сообщение, (г) цитату его слов,
  (д) команду /..., (е) [ON-DOMAIN тема, если нужно].
- Всё остальное — тишина БЕЗ вызова LLM (экономия токенов).
- NO META RULE (в системный промпт, жёстко): агент НИКОГДА не комментирует
  свои настройки/триггеры/причины молчания («меня не тегнули», «отвечаю
  только на упоминания»). Не для него сообщение — ноль ответа. Отвечает —
  только по сути, как живой коллега.

### 5. ПРОАКТИВНОСТЬ (управляемая, не спам)
- Проактивные функции — ОТДЕЛЬНЫЙ daemon-поток, ВЫКЛЮЧЕННЫЙ по умолчанию.
  Включается только явным решением владельца. (Урок: незапрошенные
  дайджесты раздражают — Стефан потребовал вырезать.)
- Разрешённая проактивность: (а) эскалация критики владельцу НЕМЕДЛЕННО
  (не ждать вопроса), (б) ответ на события своего домена из общих файлов
  (tracker/outbox), (в) [ПЕРИОДИЧЕСКИЕ ЗАДАЧИ, если владелец одобрил].
- Каждое проактивное сообщение должно проходить тест: «владелец просил
  об этом?» Если нет — в лог, не в чат.

### 6. МУЛЬТИАГЕНТНАЯ ИНТЕГРАЦИЯ
- Регистрация в entities/registry.json оркестратора: имя, роль, бот,
  scope, каналы.
- Общение агент↔агент: через общие файлы (outbox_*.md, tracker) или через
  оркестратора. Прямые вызовы чужих ботов запрещены.
- Эскалации: критика (люди/деньги/юр.риски) → владельцу [chat_id] с
  фактами и планом Б. Никогда не решать за владельца.
- Гео/этика: [ОГРАНИЧЕНИЯ, напр. полный игнор РФ-региона].

### 7. НАДЁЖНОСТЬ
- Fallback-цепочка моделей при 429/502/timeout (hot-reload списка).
- Лог всего жизненного цикла в [имя]_agent.log: старт (pid, bot id),
  каждый poll err, создание агентов per-chat, эскалации.
- Watchdog (если нужен): отдельный cron с проверкой pid-lock, НО он должен
  использовать ТОТ ЖЕ lock-механизм (иначе плодит дубли → 409).
- Голос/фото: [если нужно — Whisper transcript → как текст; vision → анализ].

### 8. КРИТЕРИИ ПРИЁМКИ
1. Процесс ровно один; в логе свой bot id; 3 минуты полла без 409.
2. В личке отвечает; в группе молчит без триггера; на триггер отвечает.
3. Ни одного мета-комментария о настройках в любом канале.
4. Незапрошенных сообщений нет; эскалация доходит владельцу.
5. Перезапуск скриптом: kill → 40 сек → start → без 409.

## Чек-лист превращения существующего текстового бота (кратко)
1. Вынести личность в system_prompt.md, знания в Agents.md.
2. Заменить «текст в LLM» на AIAgent ядра с toolsets + памятью per-chat.
3. Транспорт привести к правилам §3 (токен, lock, GET, retry-политика).
4. Врезать фильтр §4 + NO META RULE.
5. Проактивность — только по §5 (по умолчанию OFF).
6. Зарегистрировать в registry.json, настроить эскалации §6.
7. Прогнать приёмку §8.
