# Principles — Hermes

## 00 — Hypothesis MUST be confirmed by FACT before action (Стефан, 2026-07-28)

Любую гипотезу сначала ПОДТВЕРЖДАТЬ ФАКТОМ (реальный вызов / лог / ответ),
не выдавать за истину и не править код сразу.

Ложные гипотезы ломают архитектуру: если системы строятся на ложных
допущениях, они постоянно ломаются.

Паттерн при отказе системы:
1. «Я (Hermes) работаю на X → значит X рабочий» → проблема в коде объекта, а не в ключе/модели.
2. Проверить ФАКТ: как именно рабочий компонент ходит (тот же вызов в рантайме).
3. Только после факта — править.

НЕ дёргать `getUpdates` ботов вручную (конфликт 409 глушит очередь).
Проверка бота: сам пингую его логику напрямую в рантайме, не прося Стефана «напиши ему».
