# Правила Стефана (Stefan's Core Principles)

1. **Гипотезу сначала ФАКТ, потом правка:** Любое предполагаемое решение должно опираться на доказанные факты из реального вывода инструментов.
2. **Автономность при сбоях:** При любом падении или ошибке зафиксируй причину и авто-доделай с точки остановки, без вопросов "что дальше".
3. **Самопроверка сообщений:** Перечитывай свои сообщения, лови самоупоминания ошибок/падений и устраняй сразу.
4. **Конфиденциальность и безопасность:** Подтверждение только для опасных удалений. Токены и секреты хранить изолированно.
5. **Запрет отправки от имени Стефана (Userbot Security):** Доступы от личного аккаунта Telegram (юзербот `.session`) используются ИСКЛЮЧИТЕЛЬНО для чтения/сбора информации (парсер каналов, точки, сигналы). Запрещено отправлять сообщения от имени аккаунта Стефана. Все агенты и боты пишут строго от собственных бот-аккаунтов.
6. **Обход Telegram Security Guard (OTP Code Block):** Запрещено передавать 5-значные SMS/OTP коды входа в Telegram текстом в чатах (Telegram 777000 аннулирует их и блокирует IP). Вход и авторизация юзербота осуществляются только через файл `.session` (Tailscale / Telegram document upload).
7. **Хостинг и Синхронизация Канбанов:** Все 6 канбан-досок агентов базируются исключительно на Vercel (`https://<agent>-kanban.vercel.app`). Запрещен деплой/хостинг канбанов на `aavalanche.com`. Канбаны поддерживают двунаправленную синхронизацию с `https://dev.aavalanche.com/kanban_api.php` и отображают все текущие задачи и кроны агентов.
8. **Маршрутизация выгрузки файлов:** Файлы с Google Диска запрашиваются и скачиваются напрямую через Google Drive API. Файлы с ПК Стефана выкачиваются по Tailscale (если ПК в сети) и отправляются в Telegram.
9. **Изоляция сфер ответственности агентов и Канбан-досок:** Каждый агент несёт ответственность исключительно за свой функционал и контролирует строго собственный профиль и Канбан-доску (например, Алистер отвечает только за `alistair-kanban`). Запрещено перекладывать или смешивать управление канбанами между агентами.
10. **Единый источник правды Серварики (Single Source of Truth):** Любые изменения профилей, промптов (`SOUL.md`), конфигураций и навыков производятся на Серварике (`/opt/hermes/`). Локальные папки Windows (`C:\Users\Stefan\AppData\Local\hermes\`) зеркалируют серверный оригинал через Git.
11. **Честный 3-уровневый Хелс-чек Субагентов (3-Level Agent Health Check):** Проверки `systemctl is-active` недостаточно (процесс может висеть без краша). Обязателен 3-уровневый диагностический протокол:
    1) **OS Level:** `systemctl is-active` (статус процесса в systemd);
    2) **Telegram API Level:** Вызовы `getMe` и `getWebhookInfo`/`getUpdates` (валидность токена, размер `pending_update_count`);
    3) **Journalctl Logs Level:** Логи `journalctl` на `ReadTimeout`, `TimedOut`, `Blocked unauthorized user` или зацикливание перезапусков.
12. **Уведомления о перезапуске и восстановлении шлюзов (Gateway Shutdown & Restoration Notifications):** При отправке сообщения "Gateway Shutdown" (из-за внутренних процессов, системного обслуживания или перезапуска) агенты и боты ОБЯЗАНЫ после успешного восстановления работоспособности отправить пользователю короткое подтверждение ("успешно восстановлены").
13. **Изоляция секретов и синхронизация .env через Tailscale SSH (Secrets Isolation & Direct SSH Sync):** Файлы секретов и `.env` конфигураций с боевыми API ключами ЗАПРЕЩЕНО фиксировать в Git или передавать через публичные/приватные репозитории. Синхронизация `.env` между ПК Стефана и VPS осуществляется строго по прямому шифрованному каналу Tailscale SSH/SCP (`/opt/hermes/profiles/<agent>/.env`).
14. **Строгая валидация и запрет галлюцинаций вакансий (Executive Career Scanner Grounded Citations):** Все вакансии и ссылки в ежедневных отчетах от агентов обязаны формироваться только на основе реального вывода скраперов/API. Запрещено выдумывать вакансии, компании, метрики совпадения или видоизменять URL-адреса.
15. **Запрет Device Code Flow для личных Microsoft Accounts (Personal MSA MS To-Do Sync):** Личные аккаунты Microsoft (`@i.ua`, `@outlook.com`, `@hotmail.com`) блокируют Device Code Flow (`login.microsoft.com/device`) на облачных серверах с ошибкой `Selected user account does not exist in tenant 'Microsoft Services'`. Синхронизация MS To-Do производится строго через локальный PowerShell Graph модуль на ПК Стефана с переносом JSON-слепка на VPS по Tailscale.
16. **Форматирование отчётов и уведомлений кронов (No HTML tags, strictly Markdown):** Для всех агентов кластера во всех типах уведомлений и отчетов (в Telegram ЛС, группы, сводки) использовать ТОЛЬКО чистый Markdown (`*bold*`, `_italic_`, ` `code` `) и эмодзи. СТРОГИЙ ЗАПРЕТ на использование HTML-тегов (`<b>`, `<code>`, `<i>`, `<pre>`), так как шлюз Telegram или парсер Telegram Bot API падает либо отображает сырые теги при несовпадении parse_mode.
17. **Модельная архитектура экосистемы и защита от Drift Guard:** Основная модель экосистемы — `gemini-3.8-flash`. Профиль Archie (`@WordCraftBot`) в чате и его крон-задачи генерации блогов работают строго на `claude-sonnet-5`. При смене глобальной модели обязательно обновлять baseline всех 36 крон-задач в расписаниях (или пинить критические задачи на явные модели), чтобы исключить срабатывание блокировки `Inference Config Drift Guard` (`Skipped to prevent unintended spend: global inference config drifted since this job was created`).
18. **Регистрация исследовательских репозиториев как системных навыков (Skills in Ecosystem Registry):** Любые сторонние репозитории или кодовые фреймворки (например, репозитории AfterQuery), развернутые в профилях агентов, должны быть оформлены в виде файлов `SKILL.md` (с YAML-фронтматтером, описанием роли, триггерами и инструкциями) в директории навыков и внесены скриптом синхронизации в единый реестр Google Таблицы.
19. **Обязательный параметр `workdir` для фоновых Git операций:** При запуске фоновых процессов через терминал (`background=true`), таких как `git push origin master` или `git pull`, всегда обязательно явно указывать рабочий каталог (`workdir: "/opt/hermes"`), чтобы предотвратить падение команд с кодом 128 (`fatal: not a git repository`).
20. **Доступ к моделям подписки Nous Research и очистка промо-моделей:** Все агенты экосистемы (включая OpenClaw) имеют равный доступ к моделям активной подписки Nous Research через единый портальный `access_token` (а не временные `agent_key`). Промо-модели с истекшим сроком бесплатного действия (HTTP 404 / ended) немедленно вычищаются из мониторинга и конфигураций.
