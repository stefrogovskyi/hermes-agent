# Case: AfterQuery 7 Repositories Packaging into Hermes System Skills & Ecosystem Registry Sync

**Date:** 2026-09-03  
**Domain:** `agent_club` / `software_development` / `ai_infra`

## Context
В профиле Алистера (`/opt/hermes/profiles/alistair/repos/afterquery/`) были развернуты 7 автономных исследовательских кодовых репозиториев AfterQuery. Однако в вечернем отчете реестра компонентов экосистемы они не учитывались как навыки (Skills), поскольку не имели формата `SKILL.md`. Стефан уточнил статус AfterQuery в системе. По согласованию все 7 фреймворков были упакованы в официальные системные навыки Hermes и внесены в единый реестр экосистемы в Google Sheet.

## Structure of Packaged Skills
Все 7 репозиториев оформлены как полноправные системные навыки в `/opt/hermes/skills/research/afterquery/`:
1. `afterquery-mcp-atlas` — Эталонный бенчмарк и среда валидации tool-use для 36 кастомных MCP-серверов перед релизом.
2. `afterquery-harbor` — Архитектура фабрики верификаторов (Verifier Factory) и жесткий анти-галлюцинационный контроль перед сдачей задач.
3. `afterquery-mle-reasoning` — Среда локализации багов и автопочинки упавших парсеров/скриптов при смене структуры внешних сайтов.
4. `afterquery-finance-qa` — Стресс-тестирование математической и финансовой логики LLM в расчетах ставок фрахта и маржинальности.
5. `afterquery-ide-bench` — Оценка качества работы автономных кодинг-агентов на реальных задачах разработки.
6. `afterquery-skyrl` — Фреймворк RL-дообучения reasoning-моделей под логистику.
7. `afterquery-anvil` — Генерация синтетических данных и цепочек рассуждений для сложных кейсов.

## Implementation & Git Workflow Pitfall
1. Созданы 7 файлов `SKILL.md` со строгим YAML-фронтматтером, подробными инструкциями, командами запуска и триггерами вызова.
2. Запущен скрипт синхронизации `ecosystem_sync_reporter.py`, который добавил 7 новых записей в Google Таблицу (общий реестр компонентов кластера достиг 1016 записей по 6 колонкам).
3. **Git Workflow Pitfall:** При попытке запустить `git push origin master` через фоновый процесс `terminal(background=true)` без явного указания директории команда упала с ошибкой:
   `fatal: not a git repository (or any of the parent directories): .git (exit code 128)`.
   **Исправление:** Для всех фоновых вызовов Git команд обязательно явно передавать `workdir: "/opt/hermes"`. После передачи явного `workdir` фоновый пуш завершился штатно с `exit code 0`.

## Key Takeaways
- Любые кодовые базы и внешние фреймворки, подключенные агентам, должны получать интерфейс `SKILL.md` для включения в оркестрацию и отображения в реестре экосистемы.
- Фоновые команды терминала обязаны иметь явный параметр `workdir`.
